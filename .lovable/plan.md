# إصلاح النشر ورفع ذكاء الموظفين والمحادثات

## النتيجة المستهدفة
- نشر موثوق عبر Pipedream مع تشخيص واضح لكل منصة، واختبار فعلي قبل اعتبار الربط صالحاً.
- كل موظف يجيب كشخصية متخصصة متسقة، يستفيد من ملف العلامة والذاكرة والأدلة والمحادثة الحالية دون خلط.
- محادثات متعددة محفوظة لكل موظف، مع إنشاء محادثة جديدة والتنقل بين المحادثات السابقة.
- ذاكرة طويلة الأمد قوية ومفتوحة المصدر مبنية داخل Supabase، من دون خدمة خارجية ثقيلة أو تكلفة لازمة الآن.

## 1) إغلاق مشكلة النشر عبر Pipedream
- نقل ربط Meta من بناء رابط يدوي إلى Pipedream Connect SDK حيث تُمرَّر `oauthAppId` و`oauthScopeProfile` مباشرة، مع fallback واضح، وعدم اعتبار الحساب «جاهزاً» لمجرد أن حالته connected.
- إضافة فحص قابلية النشر بعد الربط: الصلاحيات المطلوبة، وجود Page Access Token، مهام الصفحة، وحساب Instagram احترافي عند الحاجة.
- اختيار الحساب والصفحة المقصودين بدلاً من أول صفحة دائماً، وعدم تفضيل ربط قديم/غير صحي؛ حفظ أخطاء المزامنة بدلاً من تجاهلها، ومنع مزامنة حساب من حذف حالة منصة أخرى خطأً.
- توحيد نشر Facebook النصي/الصور/الفيديو وInstagram الصور/Reels مع أخطاء عربية قابلة للتنفيذ، ثم اختبار منشور غير علني وحذفه تلقائياً.
- معالجة السجلات القديمة الفاشلة: إعادة فتح ما فشل فقط بسبب «غير مربوط» بعد نجاح التحقق، دون إعادة نشر تلقائي مفاجئ.

### قيد خارجي مؤكد
الاختبار الحي أعاد خطأ Meta رقم 200: الربط الحالي يمنح `pages_show_list` فقط ولا يمنح `pages_manage_posts` و`pages_read_engagement`. الكود يستطيع اكتشاف هذا ومنع الفشل الغامض، لكن نجاح Facebook/Instagram فعلياً يتطلب إضافة تطبيق Meta OAuth إلى Pipedream بصلاحيات Advanced Access معتمدة (`pages_manage_posts` و`pages_read_engagement`) وإتمام Business Verification ثم إعادة الربط. يمكن اختبار التطبيق قبل الاعتماد بحساب مضاف كـ Admin/Developer/Tester. لن نخزن أي توكنات Meta داخل التطبيق.

## 2) نظام محادثات متعددة محفوظة
- إنشاء جدول `conversations` مرتبط بمساحة العمل والموظف، مع عنوان، وآخر نشاط، وقواعد وصول تمنع أي مساحة من قراءة محادثات غيرها.
- إضافة `conversation_id` إلى الرسائل، وإنشاء محادثة «المحادثة السابقة» لكل موظف وربط كل الرسائل الحالية بها بلا فقدان.
- تمرير المحادثة المحددة في الرسائل الحرة والقدرات، وقصر سجل السياق على هذه المحادثة فقط.
- إضافة قائمة محادثات داخل شاشة الموظف، زر «محادثة جديدة»، إعادة تسمية، وحذف بتأكيد؛ يبقى الرابط القديم يفتح آخر محادثة تلقائياً.
- توليد عنوان قصير من أول رسالة، وتحديث «آخر نشاط» مع كل رد.

## 3) رفع جودة ردود الموظفين
- فصل تعليمات مشتركة ثابتة عن تعليمات كل تخصص، وترتيب السياق بوضوح: الهوية → المهمة → حقائق العلامة → الأدلة الحية → الذاكرة → سجل المحادثة → صيغة المخرج.
- فرض نمط قرار داخلي قبل الإجابة من دون إظهار التفكير: فهم الهدف، التحقق من الأدلة، اختيار الإجراء، ثم تسليم نتيجة مباشرة.
- إضافة معايير تقييم لكل موظف (دقة، اكتمال، ملاءمة للسوق العربي، صدق التنفيذ، خطوة تالية) ومحاولة إصلاح واحدة تلقائياً للمخرجات الناقصة أو JSON المقطوع.
- منع الادعاءات الوهمية والخلط بين «أعددت المحتوى» و«نشرته»، مع إحالة ذكية للموظف المختص فقط عند الحاجة.
- اختبارات ثابتة لأسئلة قصيرة، مهام طويلة، نقص البيانات، منصات غير مربوطة، وتعارض تعليمات الذاكرة.

## 4) ذاكرة مفتوحة المصدر مناسبة للبنية الحالية
- الإبقاء على التطبيع العربي والاسترجاع الحالي كمسار سريع، وتطويره داخل Supabase بدلاً من إدخال خادم Python أو Neo4j.
- إضافة ذكريات ذرية مستخلصة من المحادثات: تفضيل، حقيقة، قرار، قاعدة، أو تصحيح؛ مع المصدر، الثقة، وقت الصلاحية، وآخر استخدام.
- استلهام نموذج Mem0 لاستخلاص/دمج الحقائق، ونموذج Graphiti للحقائق الزمنية، مع تنفيذ TypeScript وPostgres محلياً.
- إضافة بحث هجين: مطابقة عربية حالية + بحث نصي في Postgres، ثم pgvector لاحقاً عندما يتوفر مسار embeddings موثوق؛ لا تُرسل أسرار أو بيانات مستخدم إلى مستودع خارجي.
- ذاكرة العلامة مشتركة بين الموظفين، وملخص المحادثة خاص بالمحادثة؛ التصحيحات الأحدث تلغي القديمة بدل تكديس التناقضات.

## 5) التحقق والتسليم
- تطبيق تغييرات قاعدة البيانات عبر ترحيل واحد آمن مع النسخ الاحتياطي المنطقي للرسائل القديمة وقواعد الوصول والفهارس.
- تشغيل اختبارات موجهة للنشر، المحادثات، الذاكرة، وبناء التطبيق.
- اختبار بصري على سطح المكتب والهاتف: إنشاء محادثتين لنفس الموظف، الرجوع للتاريخ، إرسال قدرة، والتأكد من عدم خلط السياق.
- اختبار Pipedream لكل حساب متصل؛ توثيق المنصات الجاهزة فعلاً والمنصات التي تنتظر اعتماد OAuth خارجي.

## تفاصيل تقنية
- الملفات الأساسية: `pipedream.server.ts`, `pipedream.functions.ts`, `pipedream-publish.server.ts`, `social-inbox.server.ts`, `ai.functions.ts`, `nour-run.server.ts`, `memory.server.ts`, `data.ts`, وشاشات المحادثة.
- لا تغيير لإطار المشروع، ولا Supabase Edge Functions، ولا تخزين مفاتيح خاصة في المتصفح أو الجداول العامة.
- المستودعات المرجعية: `mem0ai/mem0` و`getzep/graphiti`; لا نعتمد تشغيلهما كخدمة داخلية حالياً لأنهما يحتاجان Python/قواعد إضافية لا تناسب بيئة التطبيق.
